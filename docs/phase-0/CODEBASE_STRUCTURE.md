## 5. Data layer (`src/lib/content`)

Pages never import sample data directly. They call async functions in `repository.ts`, which
today filter in-memory arrays. This is a clean seam: the function bodies can later switch to a
database without changing pages.

| File                                                                     | Role                                                                   |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| `types.ts`                                                               | Content model (Tool, Category, Guide, Prompt, Workflow, Deal, pricing) |
| `repository.ts`                                                          | Read access; two functions use `"use cache"` + `cacheLife("hours")`    |
| `tool-query.ts`, `deal-query.ts`, `prompt-query.ts`, `workflow-query.ts` | URL-driven filter and sort logic                                       |
| `search.ts`, `text-match.ts`                                             | Keyword search across content types                                    |
| `pricing.ts`, `deal-status.ts`                                           | Derived freshness and offer status                                     |
| `compare.ts`, `labels.ts`, `prompt-utils.ts`, `workflow-utils.ts`        | Helpers                                                                |
| `sample/*.ts`                                                            | Fictional records                                                      |

Sample record counts: 23 tools, 14 categories (including subcategories), 6 guides, 4 workflows,
10 library prompts (15 prompt pages including tool-page prompts), 8 deals. All are fictional and
flagged `isSample: true`; outbound links use `example.com`.

## 7. Database drafts (`supabase/migrations`)

Every file opens with "NOT applied anywhere yet".

| File                        | Tables                                                                        |
| --------------------------- | ----------------------------------------------------------------------------- |
| `0001_catalog_schema.sql`   | `categories`, `tools`, `tool_categories`, `tool_alternatives`, `tool_sources` |
| `0002_deals_schema.sql`     | `deals`, `deal_sources`                                                       |
| `0003_pricing_schema.sql`   | `tool_pricing`, `pricing_plans`                                               |
| `0004_prompts_schema.sql`   | `prompts`, `prompt_variables`, `prompt_categories`, `prompt_tools`            |
| `0005_workflows_schema.sql` | `workflows`, `workflow_steps`, `workflow_step_alternatives`                   |

Row level security is enabled on all 16 tables. The only policies are public `select` on
published rows; there are no write policies by design (writes are meant to go through server code
with the service-role key). `admin_notes` columns are hidden from public roles with column
privileges. There are no user, profile, role, AutoFlow, submission, audit or job tables.
