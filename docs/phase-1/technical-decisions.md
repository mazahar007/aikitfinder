# Phase 1 Technical Decisions

Each entry: the decision, why, and what it costs. Owner decisions are in
`docs/phase-0a/DESIGN_DECISION_LOG.md`; these are the engineering choices made inside them.

| #    | Decision                                                                                                               | Why                                                                                                                                 | Cost or follow-up                                                                                           |
| ---- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| T-01 | One root layout with three route groups                                                                                | Moving between products is a client navigation, not a reload; one account dialog serves all three                                   | Product identity must be set on `<html>` by script, not by separate layouts                                 |
| T-02 | Product identity through token overrides on `data-product`                                                             | Shared primitives restyle with no per-product variants                                                                              | Tokens must stay complete for all three products and both themes                                            |
| T-03 | Theme stored per product; Directory keeps the key `theme`                                                              | Decision F-02; existing visitors keep their choice                                                                                  | Three keys in `localStorage`                                                                                |
| T-04 | Parent homepage keeps its own stylesheet, scoped under `.akf-parent`                                                   | The approved design had to be reproduced exactly; rewriting 2,500 lines into utilities risked visual drift                          | Two styling approaches in one repository. Parent components are not reusable elsewhere                      |
| T-05 | Fish engine kept as JavaScript with a typed declaration file                                                           | It is the approved, pixel-tested code; converting it to TypeScript would have meant re-verifying every behavior for no visible gain | Not type-checked internally                                                                                 |
| T-06 | Engine loaded on idle, after first paint                                                                               | Text and buttons are usable before any animation code runs                                                                          | The fish appears a moment after the page                                                                    |
| T-07 | On phones the canvas covers only the fish lane                                                                         | Fewer pixels to clear and draw each frame                                                                                           | Lane position is measured from the layout                                                                   |
| T-08 | Accounts switched off by one flag, `authStatus.enabled`                                                                | No Supabase project exists. A disabled form is honest; a placeholder login is not                                                   | Nothing account-related can be tested end to end yet                                                        |
| T-09 | Workspace shown as a read-only preview while accounts are closed                                                       | The owner can review the layout now; there is no user data to expose                                                                | Must be re-checked when accounts open: signed-out visitors then get only the sign-in prompt (already coded) |
| T-10 | One labeled sample project, in preview mode only                                                                       | Makes the project screens reviewable; never shown to a signed-in user                                                               | Remove when real projects exist, if preferred                                                               |
| T-11 | One personal workspace per user per product; no teams table                                                            | Owner decision: no teams, no billing                                                                                                | Adding teams later means a membership table and new policies                                                |
| T-12 | Profiles and workspaces created by a database trigger                                                                  | The browser never needs insert rights on them                                                                                       | Trigger must be kept in step with the product list                                                          |
| T-13 | No table for API integrations or social connections                                                                    | AI keys are central and server-side (F-04), so users store none. Channel tokens need an encryption design first                     | Listed in `remaining-work.md`                                                                               |
| T-14 | No Python backend in Phase 1                                                                                           | Nothing built in this phase needs it                                                                                                | The approved architecture still calls for it                                                                |
| T-15 | QA scripts use Playwright from the environment, not as a dependency                                                    | No new dependencies without approval                                                                                                | The script needs Playwright available to run                                                                |
| T-16 | Unknown project IDs: not-found screen, first response may be HTTP 200                                                  | Partial prerendering sends the shell before the lookup finishes; later requests return 404                                          | Workspace pages are `noindex`, so no search impact                                                          |
| T-17 | Authentication runs on the server only; no Supabase client in the browser                                              | Session cookies can be HttpOnly, so page scripts cannot read tokens; the homepage ships no auth library                             | Headers ask `/auth/session` once per page load                                                              |
| T-18 | The app uses the publishable key only                                                                                  | Row level security is the access control; a secret key in the app would bypass it                                                   | Admin tasks (test users, future admin tools) need a separate, server-only path                              |
| T-19 | Sign-up, log-in and log-out are Server Actions followed by a full page load                                            | Every header and page reflects the new state; nothing rendered for the previous user survives                                       | One extra page load per sign-in                                                                             |
| T-20 | Error messages are mapped to a fixed set of plain sentences                                                            | Provider wording and internals are never shown; sign-up does not reveal whether an address is registered                            | New Supabase error codes fall back to a generic message                                                     |
| T-21 | Migrations applied through the Supabase Management API, one transaction each, with history recorded in the CLI's table | No CLI or database password in this environment; the history table keeps `supabase db push` usable later                            | Version names are `0001`–`0007`, not timestamps                                                             |
| T-22 | Migration 0006 narrowed before first apply: column-level grants, no access for visitors                                | A mistake in a policy cannot expose or change more than intended                                                                    | New columns need an explicit grant                                                                          |
| T-23 | Password minimum of 8 enforced by the app; project setting left at 6                                                   | Project settings were not changed without approval                                                                                  | Recommend raising the project setting to match                                                              |
| T-24 | On touch screens, small controls grow to 44 px (`pointer-coarse`)                                                      | Meets the tap-target rule without changing the desktop look                                                                         | —                                                                                                           |
| T-25 | "New project" stays disabled                                                                                           | Creating projects is next-phase work                                                                                                | The signed-in workspace is empty until then                                                                 |
